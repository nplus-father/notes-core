# MODEL-ROUTING — 哪些工作值得花高階模型額度

**這份是什麼**：星系的工作分派原則——**哪些留給 Fable（額度稀缺、按需分配），哪些一般模型
＋驗證網就夠**。手維護；判準改變時直接改這裡，不要另立第二份。

**為什麼需要**：2026-08-24 定案前的預設假設是「難的工作＝導覽（guide），所以導覽給 Fable」。
拿資料一看，這個假設有一半是錯的，而錯的那一半會浪費最貴的額度。

---

## 開 session（任何模型）：從這裡起手

**這份就是入口**，但它只寫原則，不存清單——清單會過期，指令不會。
Andrew 問「現在該做什麼」時，先跑三行對現況，再**依你是哪個模型**分流：

```bash
cd /home/andrew/workspace/andrew/notes

grep -A6 '^## 進行中' notes-core/docs/ENRICH-BACKLOG.md   # ⓪ 有沒有上一輪沒收尾的（先收）
notes-core/tools/tier-evidence.py                          # ① 判層存量（逐站）
cat notes-core/docs/DEEPEN-READY.md                        # ② enrich 排序（頁/書愈低愈優先）
```

**分流（Fable 額度寶貴，先看自己是誰）**：

- **你是 Fable** → 只做 §一的三件事：判層殘餘的裁決、第二輪深挖的**選題**（開單給代理）、
  時機成熟的導覽；順便抽查上次 Opus 產出（協議見 §四）。
- **你是 Opus／Sonnet** → 做 §三表格裡標 Opus 的工作（第二輪起草、BST 系列、體檢、
  導覽對帳、盤點）。遇到 Fable 級判斷（主題歸屬、選題、導覽寫作）**停下來留單**
  （寫進 ENRICH-BACKLOG「進行中」），不要硬判。
- 兩者共用同一條流水線與驗證網（memory `fable-session-entrypoint` 有完整步驟）。

貼給 Fable 的話術，兩條主線各一句：

> **判層**：「讀 `notes-core/docs/MODEL-ROUTING.md` 與 `note-check` §1.3–1.4，
> 跑 `notes-core/tools/tier-evidence.py <station> --detail`，逐本裁決那些書該判哪一層。
> **只輸出 JSON 決策，不要改檔**——套用另外走腳本。」
>
> **enrich**：「讀 `note-check` §6 的書本位紀律，進 `<station>` 跑 `/note-check --enrich`。
> 每個主張都要掛得住 anchor，掛不住就不要寫。」

**判層為什麼要「只輸出決策、不改檔」**：讓模型逐筆改 TS entry 必壞語法（2026-08-24
首輪實測，90 筆就壞）。決策用 JSON 交回，套用走腳本，語法零風險而且可對帳：

```bash
notes-core/tools/apply-tiers.py <decisions.json>          # 先乾跑看筆數
notes-core/tools/apply-tiers.py <decisions.json> --apply  # 寫入
notes-core/tools/tier-audit.py                            # **必跑**：套用後有沒有製造違約
```

決策 JSON 的格式在 `apply-tiers.py` 檔頭，跟 `tier-evidence.py --json` 同形狀，
所以模型只要照著那份的樣子回填 `tier` 就行。

**交回來之後是我的工作**（不必再花高階額度）：套用、跑 `tier-audit.py`、修違約、
升版鋪開。分工是**來回交錯**，不是單向接力。

## 判準：貴的額度要花在「難、而且不會被下一輪推翻」的工作

兩個條件缺一不可。

- **難**：要讀原文、要判斷、錯了不容易被機器抓到。
- **不會被推翻**：產出的壽命夠長。寫一份下個月就要重寫的東西，用多好的模型都是浪費。

反過來，**有驗證網的結構化決策不該吃高階額度**——那種工作「便宜模型＋驗證網」勝過
「昂貴模型沒驗證網」。2026-08-24 那輪各級代理都出過事（三筆杜撰、HTML entity 污染、
一個把地面真相講反的宣稱），全部是驗證抓到的，不是模型等級抓到的。

## 一、留給 Fable

### 1. enrich：把架上的書挖成概念頁（**第一順位**）

這是真正難的工作——要讀原文、掛得住 `anchor`、不能杜撰。寫出來的概念頁是
站的實質內容，不會像導覽那樣被下一輪推翻。

> **第一輪（填缺口）已於 2026-08-25/26 完成**：16 站、248 本裁決、105 頁新頁＋4 頁補強，
> 每本 spine 至少一頁承載、稽核四違約全零（詳帳在 ENRICH-BACKLOG）。從此 enrich 的
> Fable 級工作只剩**第二輪深挖的「選題」**——一本大部頭第二頁該切哪個概念、跟第一頁
> 怎麼分工。選題錯了寫得再好也是重疊頁，這是整條線裡最像判層的判斷。

最新排序永遠看 [DEEPEN-READY.md](./DEEPEN-READY.md)（每次重算），不要在這裡抄表。

### 2. 判層的爭議少數（**第二順位**）

**不是全部**。判層依據多半本來就躺在 repo 裡——引用散布（被 ≥3 個不同的頁引用＝既成事實
spine）、姊妹站有沒有收（→ delegated）、`group`／`note` 的既有文字。2026-08-24 首輪實測：
261 本「未挖」裡 192 本是判過的決定，真正拿不準的大約五分之一。

**作法**：先用工具算出證據包（`tools/tier-evidence.py`）、把明確的自動判掉，只把**有爭議的
短清單**交給 Fable。把 1031 本原封丟給它，是拿高階額度做查表。

2026-08-24 實跑並套用：**1031 本裡 674 本（65%）證據充分、已自動判掉並上線**，
未判層降到 **295 本**（分佈在 31 站，其中 87% 帶有 `note`）。稽核在套用後仍是
真欠債 1、空頭支票 0、漏接 0、衝突 0——沒有因為批次判層製造出新的缺口。

**那 295 本就是 Fable 的工作量**，逐站清單跑 `tools/tier-evidence.py --detail`。
它們多半有實質的 `note`（「系列中最明顯的缺口」「獨著中的代表作」），要判的是
「該不該有專屬概念頁」，不是查表。

> 2026-08-25/26 十六站連打後，**存量 310 → 81 本**（分佈在 11 個中小站）。下面那條
> 「判斷疊判斷」的警告在實戰中兌現了：工具果然把《藍海策略》自動判給 startup-note，
> 依本檔明文推翻、判 spine 於 business-strategy 並開頁。第二輪 delegated 一律人工複核，
> 這條紀律持續有效。
>
> **2026-08-26 判層收官：全星系未判層歸零**（Fable 清掉最後 15 站 109 本，含 81 本裁決）。
> 裁決同時生成第二輪選題清單（35 筆＝26 新頁＋9 補 anchor，見 ENRICH-BACKLOG），
> 所以「判層」與「選題」在收官輪合併成了同一個動作。此節保留作方法論；
> 日後新書進站產生的零星未判層，比照辦理。
>
> **同日 Opus 把那 35 筆全部起草完成**（26 新頁＋9 補 anchor，橫跨 11 站，全部 push），
> 之後又清掉 roadmap 承諾債 9 頁與第三輪 8 頁。**判層歸零後「哪裡還薄」的新訊號**
> 已固化成 `export-deepen-targets.py`：spine × 章節數 ≥30 × 被引頁數 ≤1（`tier-audit`
> 抓不到這一類，它只報零引用）。首跑 156 本候選、44 站——**它只排序，開單仍留 Fable**。
> 收工驗證：`tier-audit.py --all` 全星系 1922 本藏書，**六類違規（真欠債／空頭支票／漏接／
> 文資不符／衝突／未判層）全數 0**。這是本庫第一次同時做到「藏書全判層」與「spine 全兌現」。

> **不要拿工具的輸出再餵它一次。** 套用後再跑會冒出一批新的「可自動判 delegated」，
> 但那些的姊妹站 spine 本身就是上一輪自動判的——**判斷疊判斷**。「被引用 1 次」這種
> 弱訊號經過兩層就變成「深挖歸那站」的強承諾，而結論常常是錯的（business-strategy
> 會把《藍海策略》讓給 startup-note，只因為那站引過一次；但藍海按主題本來就該歸
> business-strategy）。委託是**主題歸屬**的判斷，第二輪起一律留給人。

### 3. 導覽（**第三順位，而且要挑時機**）

導覽本身確實是最難的寫作，但**它是衰減最快的產出**，所以時機比模型重要。

> 2026-08-24 實證：hbr 與 thinking 的導覽是高階模型寫的，**幾天內就變成事實錯誤**——
> hbr 說「38 本進站、九卷正典剩三卷待挖」，實際是 43 本、九卷全落地；thinking 說
> 「42 已挖／14 待挖」，實際 47／9。文筆沒問題，是底下的事實跑掉了。
> 每一輪 enrich 都會做這件事。

**紀律：導覽最後寫，寫給「不再長」的站。** 站還在 enrich 就寫導覽，等於買一份保證要重寫的
散文。判斷標準用 [DEEPEN-READY.md](./DEEPEN-READY.md) 的「已深化」那一節。

2026-08-24 當下的狀況值得記著：32 個無導覽的站裡，**31 個還在「可深化」**（書沒挖完），
只有 `image-style-note` 一站算挖完了。所以那個時點根本沒有值得花高階額度的導覽待辦——
瓶頸不是寫導覽的能力，是站還沒準備好。

## 二、不需要 Fable

| 工作 | 為什麼 |
| --- | --- |
| **判層的明確案例** | 證據躺在 repo 裡，而且有 `tier-audit.py` 四種違約檢查＋`--verify` 對帳兩份實作 |
| **稽核與對帳** | 純機械，跑工具（`tier-audit.py`；全站健康度用 `galaxy-checkup.py`，75 站一次掃完） |
| **版面／樣式／升版** | 改 notes-core 一處、`bump-notes-core.sh` 鋪全隊，有 lockfile 驗證與 build gate |
| **盤點表機械修正** | 補 `year`、修死鏈 slug、清理格式——有生成報表指出來 |
| **導覽的「事實對帳」** | 「38 本進站」改成「43 本」不需要文采，需要的是數對。查證比寫作便宜得多 |

最後一項值得展開：**導覽過期時，多數情況不必重寫，只要對帳**。2026-08-24 修 hbr 與
thinking 的導覽就是這樣——保留原有語氣與論證，只改被現況打臉的句子。整份重寫反而會丟掉
上一輪的判讀。

**判層裁決**（主題歸屬）、**開單**（每頁的邊界、避開哪些既有頁、anchor 落哪幾章）、
**抓規格錯**。其餘（照單起草、掃描、補邊、build）全在驗證網罩著，而本檔的原則本來就是

書本位紀律接住指揮層的規格錯**（釋經之旅「四步」實為五步、fastlane 五誡是 NECST 不是

（抽驗協議＝逐頁具名事實回源 grep＋entity／anchor／雙向掃描，完整流水線記在
memory 的 `fable-session-entrypoint` 與 ENRICH-BACKLOG 各輪紀錄）。

**唯一的硬規則**：Opus 跑第二輪深挖時，**選題清單先交 Andrew（或 Fable）過目再動筆**。
選題是深挖裡唯一沒有機器驗證網的判斷——重疊頁寫得再好也是灌水。

## 四、共通紀律：驗證網比模型等級重要

不管誰做，這幾件事都要做（2026-08-24 全部踩過）：

- **交回來的稿先 grep `&gt;` `&lt;` `&amp;`**——HTML entity 污染幾乎每個代理都會犯。
- **每個 `anchor` 要驗目錄真的存在**（`[ -d books-done/**/<book>/site/content/<anchor> ]`）。
- **每個數字要自己數過**，不要沿用上游給的。連我給代理的「地面真相」都被它查出錯過一次
  （我說 2025 版《on Leadership》沒有 Goleman，其實第 6 篇就是他的〈Primal Leadership〉，
  缺的是〈What Makes a Leader?〉）。
- **工具報違約先自己確認再動手**——首輪 35 筆空頭支票裡有 21 筆是假的（雙語書名比對沒拆片段）。
